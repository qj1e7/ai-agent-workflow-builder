**Setup.**
- Stack. `n8nio/n8n:2.42.6@sha256:526daa…` on `postgres:17@sha256:2d2b89…`, no licence key on the free Community edition, and `stub.py` standing in for our API's `/internal/v1/n8n/*` routes. Images are pinned by digest as in `deploy/compose.yaml`.
- Compose project `wab-e2e-p7`: n8n on port 15721, the stub on 18041. It ran on 13 Nov 2026.
- `node-pack/` holds four throwaway nodes in plain JavaScript. Start from the Portal is a trigger that checks an HMAC signature and a 5-minute expiry. Call our API stands in for Read, Agent, Propose a change, Make the approved changes and Tell. Ask for a yes waits, and its `webhook()` checks a `mac`. Report a failure posts the Error Trigger's item. Each node reads `WAB_API_URL` and `WAB_NODE_KEY` from the environment and has no address field.
- On the first node call of each execution, the stub reads `GET /api/v1/executions/{id}?includeData=true`, the way our API would link the execution to a run, and records what it saw.
- Users. `platform@example.com` is n8n's owner, which stands in for the platform's account. Alice and Bob are ordinary members.
- The host was shared and heavily loaded (load average near 200 during development). `compose.yaml` raises three timeouts so the load did not fail runs. They change no answer.
- The final pass ran `./run.sh` and then `variants.py` on a fresh stack. `q06.txt` was run once more at the end, on the last variant's stack with the allow list on, after its output gained the mode of each call. The allow list does not touch that question.

**Run it again.** `./run.sh` makes `p7.env` with fresh keys (git ignores it), boots the stack, makes the owner and an API key (`setup.py`), and runs the questions that need no restart. `python3 variants.py` restarts n8n once per setting and runs the rest. `./run.sh q99` checks history pruning an hour after the last restart. `./run.sh down` removes the containers and volumes. Each script writes `raw/<name>.txt`. Every line passes through `lib.mask()`, so no key, password, token or resume signature is in `raw/`. `q01:7` below means line 7 of `raw/q01.txt`.

Expressions use the same engine in every node, IF and our own nodes included. In this n8n, `$env.WAB_NODE_KEY` gives `access to env vars denied`, `process.env` has no keys, `require` and `fetch` are not functions, and `this.constructor.constructor(…)` is refused before it runs (q10:28 to 30). So D8 holds, and a value in the container's environment is readable only by our nodes' code.

**Q11, the allow list.**
- With no allow list (base), n8n loads 847 types, ours as `CUSTOM.startFromPortal` and so on. An HTTP Request node publishes, runs by hand, and reaches the stand-in API (q11_base:2 to 8). This is the control.
- With the allow list naming `CUSTOM.*` (custom), n8n loads exactly the 11 types listed. An HTTP Request node is refused on publish and on a hand run with `Unrecognized node type: n8n-nodes-base.httpRequest`, and nothing reaches the stub (q11_custom:2 to 7).
- With the allow list naming `wab.*` (wab_names), our nodes do not load at all; n8n loads only the 7 n8n types (q11_wab_names:2 to 3).
- With the pack folder mounted as `/home/node/.n8n/nodes/node_modules/n8n-nodes-wab` (package), n8n loads it at start-up with no install step, as `n8n-nodes-wab.*`. With the allow list naming those, it loads exactly 11 types, refuses HTTP Request, and runs a workflow that uses `n8n-nodes-wab.callOurApi` (q11_package:2 to 8).
- In n8n's loader the allow list is applied per package, but every package drops what the list does not name, so the 300-odd LangChain nodes do not load either (q11_custom:3).

**Q12, the schedule.** The table is in `cron_table.json`, computed by n8n's own code for a fixed node key and the reference time 2026-11-13 08:30 Singapore time.
- A rule becomes a 6-field cron with seconds. n8n adds a second from 0 to 59 to every rule except "every N seconds" and a raw cron expression, so "Daily 8:00" fires at 08:00:43 for this node (q12:2). The second is `sha256("{workflowId}:{nodeId}:second")`, first four bytes, modulo 60. When a rule leaves out the minute or the hour, n8n picks them the same way (q12:3 to 4).
- Python reproduces all three numbers exactly (q12:13 to 15), so `n8n_schedule.py` can compute the true next run when it knows the workflow and node ids.
- "Every 2 days at 8:00" becomes a daily cron plus a filter that remembers the last run in the workflow's static data (q12:9). "Every 5 hours" becomes hourly plus the same filter (q12:8). Their next run cannot be computed from the rule alone.
- The times follow `settings.timezone`: the table's UTC times are Singapore times minus 8 hours.
- n8n 2.42.6 also ships a durable scheduler with catch-up, but it is off by default (`triggerNodeMode: legacy` in `@n8n/config`). Under the default in-memory scheduler a missed slot is not run later. On this loaded host n8n logged `[Cron] Missed execution deadline by 23909ms … Skipping execution as it exceeds threshold (250ms)` in a development run, so a slot can be missed while n8n is up. That line is from n8n's log, not from a raw file.

**Q14, a refused resume, and what not to do.** n8n's waiting-webhook handler passes the request to our node's `webhook()`. If it returns no `workflowData`, n8n answers with what the node wrote and leaves the execution as it was (q06:6 to 11). The real yes then resumes it (q06:12 to 13). The `throw` variant shows what goes wrong otherwise. When `webhook()` throws, n8n answers 500 `Workflow could not be started!` and still runs the execution on through output 0, the Yes exit, with an empty item. "Create ticket" called our API, and the execution ended in error, so the real yes then got 409 (q06_throw:6 to 9). The gateway would still refuse that write, because our records hold no yes, but the wait is lost.

## What the plan must change

1. **Node type names (2.2, E1, E11).** `wab.<name>` cannot exist. Built into the image the way E1 plans (`dist/` in `/home/node/.n8n/custom` with `N8N_CUSTOM_EXTENSIONS`), the names are `CUSTOM.<name>`. Mounted as a package, they are `n8n-nodes-wab.<name>` (Q11). `NODES_INCLUDE`, `workflow_check.py`, the pack smoke and the golden documents must use the real prefix.
2. **The test run's body (D4, 2.3.3).** Send `{triggerToStartFrom: {name: "Start from the Portal", data: {data: {main: [[{json: <start item>}]]}}}}` and nothing else. n8n ignores `workflowData` and runs the stored draft (Q3).
3. **The link order (2.3).** A Run now arrives with mode `webhook`. Add that case, where a `webhook` execution links by its start item and is refused without a valid one. `trigger` means the Schedule Trigger only (Q1).
4. **Which version ran (2.3.1).** Read `workflowVersionId` from `GET /executions/{id}`. It is exact for `webhook`, `trigger` and `manual` runs, so the 60-second `activeVersionId` cache is not needed. A retry with `loadWorkflow: false` has none, so use its `retryOf` execution's (Q6).
5. **The public retry blocks until the retry stops (2.3.10, `N8nStarts.retry`).** Call it from the outbox with a long timeout, never inside a request. A retry that reaches Ask for a yes answers `waiting` (Q5).
6. **Ask for a yes must not throw, and its first exit must not be Yes (2.2).** When `webhook()` throws, n8n runs output 0 with an empty item (Q14). Refuse by writing the 401 and returning `{noWebhookResponse: true}`. Order the exits so output 0 is a harmless one, for example `No answer, Yes, No, Nothing to change`, so any error path in n8n ends without a write.
7. **The error workflow for a held workflow (M4, 2.8).** Give `run_failure_reporter` `settings.callerPolicy: "any"`, and have bootstrap and the checker keep it so. Keep the sweep of `status=error` executions as the backup, as E2c plans. Error workflows never run for manual executions, so our API must watch a test run's execution itself, by the id the run call returns (Q13, Q22).
8. **The version compare (2.5).** The public `PUT` cannot compare, and sending `versionId` in its body is a 400. Keep read, compare, write, read back. Publish through `POST /rest/workflows/{id}/activate {versionId, expectedChecksum}`, which refuses a changed draft with 409 (Q18). That adds one `/rest` use.
9. **Who joins the parties for a republished version (2.5, S4).** History `authors` is a display name such as "Alice Tester", not a user id (q04:12). Use the publish timeline's `user.id` for publishers, and treat `authors` as a hint matched by name, or drop that rule (Q4).
10. **Undo after a day (2.5, section 7).** Community keeps history 24 hours, and no setting raises it. `publish {versionId}` works only for versions from the last day, plus the draft, the active and the published ones. Our stored document is the usual path for anything older (Q7).
11. **The schedule (2.4, E5, the checker).** The Planner must always set `triggerAtHour` and `triggerAtMinute`. `n8n_schedule.py` must add n8n's second, or the Portal must say "about 8:00". The checker should refuse `daysInterval` above 1 and hour intervals that do not divide 24, because their next run depends on state n8n keeps. A slot can be missed while n8n is up (Q12).
12. **Archive does not stop a waiting run (D7).** A wake still resumes it and runs the write. D7's order (expire the request first, then archive and delete) is what keeps it safe. Delete needs archive or unpublish first (Q8, Q17).
13. **Users and projects (D17, 2.1).** Public `POST /users` works on Community, so use it. Public `GET /projects` does not, so find a member's project with the owner's `GET /rest/projects` (Q9). That is one more `/rest` use.
14. **`attempt` (2.2).** A node cannot know its try number. Our API counts calls per execution and node (Q21).
15. **The evidence path (section 6).** The P7 row names `docs/evidence/prototypes/p7-n8n-engine/`. This folder is `p7-n8n-engine-facts/`, as the build brief asked.

## What the next PRs need to know

- **E1, the pack.** Use the `CUSTOM.` or `n8n-nodes-wab.` prefix. In `webhook()`, refuse by writing the 401 yourself and returning `{noWebhookResponse: true}` with no `workflowData`, and never throw. Start from the Portal can sign over `req.rawBody`, which n8n keeps for webhooks (`signed_over: rawBody`, q01:11). A node can read `this.getMode()`, `this.getExecutionId()` and `this.getWorkflow().id`, but not its try number. n8n 2.42.6 logs `WEBHOOK_URL` as deprecated in favour of `N8N_WEBHOOK_URL`.
- **E2c, failures.** The Error Trigger item's shape is in Q22. `retryOf` is present only on retries.
- **E4, `n8n.py` and the layouts.** The public API keeps the layout's settings (Q20). A `PUT` on a published workflow republishes unless `?publishIfActive=false` (q07:3 to 4). The `/rest` uses are now publication-status, publish-timeline, run, activate with `expectedChecksum`, and projects. `publication-status` reads `in_progress` while n8n moves the triggers, so wait for `status: published` with every trigger `activated` (q01:5, q07:9).
- **E5, runs.** The test run body is plan change 2. The public retry's blocking answer is plan change 5. `cron_table.json` is the golden table for `n8n_schedule.py`.
- **E7, staff accounts.** Public `POST /users` gives an invite link with a `token`, which the person's own Settings page can show. The owner's `GET /rest/projects` gives each member's personal project for the transfer.
- **E16, data nodes.** The safe list is the first row of the Q10 table.

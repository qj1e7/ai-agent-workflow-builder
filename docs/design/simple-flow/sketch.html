Simpler Core Flow

Today a support person has to learn four overlapping ideas to do one job. This sketch shows the same job as one path with three steps, four states and one rule about approval. It is a proposal: any new wording on this page still needs your OK, and nothing is built yet.

Today: the same request can go three ways

The person typed "Every day at 9am, check LangGraph for new releases". Which path they land on depends on things they can't see.

Path A

A setup card from our blocks

  1. Type the task
  2. Check the card
  3. Answer its questions
  4. Press Set up
  5. Test run, writes nothing
  6. Press Turn it on
  7. Each write: an Approver's yes
Path B

"Draft it as an n8n workflow"

  1. Type the task
  2. Press Draft it as an n8n workflow
  3. The drafter drafts it
  4. The safety checker flags it
  5. A set-up yes from an Approver
  6. Turn it on
  7. Each write: an Approver's yes
Path C

The Software watchlist

  1. Type the task
  2. "I can't do all of that"
  3. "I can't give one software its own time"
  4. Make the watchlist run every day
  5. Change, then Save

LangGraph already lives on the watchlist, which runs all software on one shared schedule. The person asked for a workflow and met a second idea instead.

Nothing you can do today goes away

  1. Any n8n block. The Planner uses our blocks when they cover the task and any n8n block when they don't, as the drafter can today (ADR 0051). The quiet "Build it with any n8n block" link on the card lets the person choose it themselves. A flagged workflow still needs an Approver's one-time yes, shown as one line on the card.
  2. Edit in n8n. "Open in n8n" stays on every workflow page, in view. Staff can still change, build and fix workflows in n8n without a technical person, as the sponsor asked. Edits made there are still checked at the write.
  3. What changes is only that the person no longer has to pick a path before they start.
